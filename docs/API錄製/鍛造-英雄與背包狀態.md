# 鍛造－英雄與背包狀態 API 錄製摘要

來源：Tampermonkey Recorder 匯出 `tools/autoy-api-recorder-2026-10-01T02-35-58-528Z.json`。

## 已觀察請求

### GET /api/profile — 帳號概況（含鍛造坊數量）

| 欄位 | 值 |
| --- | --- |
| 方法與端點 | `GET /api/profile` |
| HTTP 狀態 | 200 |
| 耗時 | 80 ms |
| 關鍵欄位 | `forgeExpanded: 4` |

`forgeExpanded` 為已擴充的鍛造坊數量（不含預設第 1 坊）；`forgeExpanded: 4` 代表共 5 個鍛造坊（`target` 1–5）。

### GET /api/heroes — 英雄列表（含鍛造狀態）

| 欄位 | 值 |
| --- | --- |
| 方法與端點 | `GET /api/heroes` |
| HTTP 狀態 | 200 |
| 耗時 | 86 ms |

**已確認的英雄 `actionState` 值：**

| actionState | 含義 | 備註 |
| --- | --- | --- |
| `0` | 閒置 | 可鍛造條件：`actionState: 0` 且 `huntZone: 0` |
| `4` | 挖礦中 | `actionTarget` = 礦區編號；`canComplete: true` 代表挖礦可完成，非鍛造 |
| `5` | 鍛造中 | `actionTarget` = 鍛造坊編號；`canComplete: false` = 進行中，`canComplete: true` = 可完成鍛造 |
| `6` | 販賣中 | 英雄掛在交易市場出售中；`actionTarget: null` |
| `7` | 修練中 | `actionTarget: null`；可帶有 `canComplete: true` |

**鍛造進行中英雄欄位範例（state 5，進行中）：**

```json
{
  "actionState": 5,
  "actionTarget": 1,
  "actionStart": "<ISO timestamp>",
  "actionCompleteTime": "<ISO timestamp>",
  "canComplete": false
}
```

**鍛造可完成英雄欄位範例（state 5，canComplete: true）：**

```json
{
  "actionState": 5,
  "actionTarget": 1,
  "actionStart": "<ISO timestamp>",
  "actionCompleteTime": "<ISO timestamp>",
  "canComplete": true
}
```

**挖礦英雄欄位範例（state 4，canComplete: true）：**

```json
{
  "actionState": 4,
  "actionTarget": 3,
  "actionStart": "<ISO timestamp>",
  "actionCompleteTime": "<ISO timestamp>",
  "canComplete": true
}
```

> ⚠️ state 4 為挖礦，不可呼叫 completeForge。

完成鍛造後英雄回到閒置：`actionState: 0`、`actionTarget: null`（已由開始鍛造錄製確認）。

## 已確認行為規則

- `forgeExpanded` 為 `N` → 鍛造坊 `target` 範圍為 1 至 `N+1`（共 `N+1` 個）。
- 鍛造中英雄為 `actionState: 5`；`canComplete: true` 時可呼叫 `completeForge`。
- 只有 `actionState: 5` 且 `canComplete: true` 的英雄可呼叫 `completeForge`。
- `actionState: 4` 為挖礦，`canComplete: true` 代表挖礦可完成，不可呼叫 `completeForge`（API 回 400）。
- 可鍛造英雄條件：`hp > 0`、`perished !== true`、`actionState === 0`、`huntZone === 0`。
- `selected: true` 的出戰英雄通常有 `huntZone >= 1`，不符合鍛造條件。

原始 JSON 僅留本機；摘要省略帳號與個資欄位。
