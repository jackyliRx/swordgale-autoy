# 鍛造－英雄與背包狀態 API 錄製摘要

來源：Tampermonkey Recorder 匯出 `tools/autoy-api-recorder-2026-10-01T02-35-58-528Z.json`。

## 已觀察請求

### GET /api/profile — 帳號概況（含鍛造坊數量）

| 欄位 | 值 |
| --- | --- |
| 方法與端點 | `GET /api/profile` |
| HTTP 狀態 | 200 |
| 耗時 | 80 ms |
| 關鍵欄位 | `forgeExpanded: 4` |

`forgeExpanded` 為已擴充的鍛造坊數量（不含預設第 1 坊）；`forgeExpanded: 4` 代表共 5 個鍛造坊（`target` 1–5）。

### GET /api/heroes — 英雄列表（含鍛造狀態）

| 欄位 | 值 |
| --- | --- |
| 方法與端點 | `GET /api/heroes` |
| HTTP 狀態 | 200 |
| 耗時 | 86 ms |

**已確認的英雄 `actionState` 值：**

| actionState | 含義 | 備註 |
| --- | --- | --- |
| `0` | 閒置 | 可鍛造條件：`actionState: 0` 且 `huntZone: 0` |
| `4` | 鍛造進行中（可完成） | `canComplete: true`；可呼叫 completeForge |
| `5` | 鍛造進行中（未可完成） | `canComplete: false`；剛開始鍛造後的狀態，需等待才變為 4 |
| `6` | 販賣中 | 英雄掛在交易市場出售中；`actionTarget: null` |
| `7` | 其他行動（休息等） | 無 `actionTarget`；帶有 `canComplete: true` |

**鍛造進行中英雄欄位範例（state 5，剛開始）：**

```json
{
  "actionState": 5,
  "actionTarget": 1,
  "actionStart": "<ISO timestamp>",
  "actionCompleteTime": "<ISO timestamp>",
  "canComplete": false
}
```

**鍛造進行中英雄欄位範例（state 4，可完成）：**

```json
{
  "actionState": 4,
  "actionTarget": 3,
  "actionStart": "<ISO timestamp>",
  "actionCompleteTime": "<ISO timestamp>",
  "canComplete": true
}
```

完成鍛造後英雄回到閒置：`actionState: 0`、`actionTarget: null`（已由開始鍛造錄製確認）。

### GET /api/heroes/{heroId}/statuses

| 欄位 | 值 |
| --- | --- |
| 方法與端點 | `GET /api/heroes/{heroId}/statuses` |
| HTTP 狀態 | 200 |
| 耗時 | 77–82 ms |
| Response | `{ "statuses": [] }` |

三名英雄的狀態均為空陣列。此端點由遊戲前端發出，非 Autoy 主動呼叫。

## 已確認行為規則

- `forgeExpanded` 為 `N` → 鍛造坊 `target` 範圍為 1 至 `N+1`（共 `N+1` 個）。
- 鍛造剛開始後英雄為 `actionState: 5`（`canComplete: false`），等待一段時間後轉為 `actionState: 4`（`canComplete: true`）才可完成。
- 可鍛造英雄條件：`hp > 0`、`perished !== true`、`actionState === 0`、`huntZone === 0`。
- `selected: true` 的出戰英雄通常有 `huntZone >= 1`，不符合鍛造條件。

原始 JSON 僅留本機；摘要省略帳號與個資欄位。
