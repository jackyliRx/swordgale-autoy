# 完成休息－出戰角色（Tampermonkey 錄製）

來源：本機原始錄製檔 `完成休息-出戰角色.json`。原始檔包含英雄資料，只保存本機，不提交公開 GitHub。

## 已確認請求

| 項目 | 值 |
| --- | --- |
| 操作 | 完成休息 |
| 方法與端點 | `POST /api/heroes/restAll/complete` |
| Request body | 無 |
| HTTP 狀態 | 200 |
| 耗時 | 65 ms |

## 回應重點

回應包含 `huntInfo` 與 `messages`：

- `huntInfo` 回報大草原第 1 層、可前行。
- `huntInfo.heroes` 有 4 名英雄，全部 `actionState: 0`、`perished: false`，且各自附有空的 `statuses`。
- `messages` 有 4 筆恢復結果，每筆對應一名回應中的英雄，內容為恢復 HP 與 SP。

## 使用規則

`restAll/complete` 是單次完成整隊休息的端點。自動流程必須先由最新 `/api/heroes` 確認勾選出戰角色全數處於休息且 `canComplete: true`，才送出這個 POST；完成後以回應的 `huntInfo.heroes` 合併狀態，再重新讀取 `/api/heroes` 驗證出戰名單和 HP／SP。

本次縮減的 `huntInfo.heroes` 沒有 `selected` 欄位，因此它本身不能證明 4 名回應英雄就是當下勾選出戰角色；出戰選取仍以完整 `/api/heroes` 回應為權威資料。
