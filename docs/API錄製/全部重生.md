# 全部重生 API 錄製摘要

來源：Tampermonkey Recorder 匯出 `全部重生.json`。此錄製包含一組重生 request／response，及其後的單一英雄詳細與狀態讀取。

## 已觀察重生請求

| 欄位 | 值 |
| --- | --- |
| 操作 | 全部重生（一般死亡角色） |
| 方法與端點 | `POST /api/heroes/reviveAll` |
| Request body | 無 |
| HTTP 狀態 | 200 |
| 耗時 | 64 ms |
| Response | `heroes`，共 3 張角色卡 |

回應中兩名勾選出戰角色均為 `selected: true`；其中存活者維持 `hp > 0`、`actionState: 0`。一般死亡的出戰角色為 `hp: 0`、`perished: false`，進入 `actionState: 3`，`canComplete: false`，並回傳約 10 分鐘後的 `actionCompleteTime`。第三張未勾選的存活角色 `selected: false`，此樣本中維持 `actionState: 0`。

## 後續讀取

同一匯出在 POST 後另有 `GET /api/heroes/{heroId}` 與 `GET /api/heroes/{heroId}/statuses`，回應單一未勾選角色的詳細資料與空狀態清單。這些是後續讀取事件，不視為 `reviveAll` 的 response。

## Autoy 使用規則與待補錄

- `reviveAll` 是帳號批次端點。錄製樣本中的未勾選角色存活且未進入重生；不能由此推斷未勾選死亡角色的伺服器反應。產品流程依使用者決定不限未勾選角色，因此呼叫後以完整 `/api/heroes` 追蹤帳號內所有一般死亡角色，直到整批可完成。
- 以各英雄 `actionCompleteTime` 排程，重新讀取狀態後，整批重生可完成時呼叫 `POST /api/heroes/reviveAll/complete` 一次完成。詳見 [全部重生－完成行動](全部重生-完成行動.md)。
- 重生完成的批次 endpoint 已由 [全部重生－完成行動](全部重生-完成行動.md) 確認。
- POST 結果不明時重新讀取狀態，不自動重送。

原始 JSON 僅留本機；摘要省略角色名稱、ID 與屬性資料。
