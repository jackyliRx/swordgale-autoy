# 全部重生－完成行動 API 錄製摘要

來源：Tampermonkey Recorder 匯出 `全部重生-完成行動.json`，共三組 request／response 配對。

## 已觀察完成請求

| 欄位 | 值 |
| --- | --- |
| 操作 | 完成全部重生 |
| 方法與端點 | `POST /api/heroes/reviveAll/complete` |
| Request body | 無 |
| HTTP 狀態 | 200 |
| 耗時 | 62 ms |
| Response | `heroes`，共 3 張角色卡 |

回應中兩名勾選出戰角色均為 `selected: true`，且都回到 `actionState: 0`、`perished: false`；已重生角色 HP 恢復至 285。另有一名未勾選存活角色，仍為 `actionState: 0`。這筆完成回應沒有 `messages` 欄位。

## 後續讀取

同一匯出包含 `GET /api/heroes/{heroId}` 與 `GET /api/heroes/{heroId}/statuses`，用於查看一名未勾選英雄詳細資料及狀態。這兩個讀取不屬於完成重生的 response。

## Autoy 使用規則

先呼叫 `POST /api/heroes/reviveAll` 啟動批次重生，依最新回應中一般死亡角色的 `actionCompleteTime` 等待；重新讀取狀態後，當整批重生可完成時呼叫 `POST /api/heroes/reviveAll/complete` 一次完成。完成後以回應的英雄狀態更新，再重新讀取完整 `/api/heroes` 驗證出戰名單與 HP/SP。

此樣本確認完成端點是整批 `/reviveAll/complete`，不應改用逐角 `completeAction`。由於啟動與完成兩筆樣本不是同一個連續請求串，正式 runner 仍須依伺服器回傳時間與即時狀態控制，不可硬編固定 10 分鐘。

原始 JSON 僅留本機；摘要不保存角色名稱、ID 或屬性資料。
