# 完成移動 API 摘要

| 欄位 | 已觀察值 |
| --- | --- |
| 方法與端點 | `POST /api/move/complete` |
| Request body | 未觀察到 |
| HTTP 狀態 | 200 |
| 最新大草原紀錄 | `2026-09-25T19:30:55.904Z`，耗時 59 ms |
| 回傳位置 | 依情境不同：初始之鎮 `0/0`，或大草原第 1 層 `1/1` |
| 最新回應 | `huntZone: 1`, `huntStage: 1`, `zoneName: 大草原`, `canForward: true`；2 名角色均回到 `actionState: 0` |
| 後續讀取 | `GET /api/zoneUsers`，200，67 ms；response 有 `users` 欄位 |

兩筆「完成移動」紀錄都回傳 `actionState: 0`，但目的地不相同：較早紀錄在初始之鎮（`huntZone: 0`, `huntStage: 0`, `canForward: false`）；「完成移動-大草原.js」在大草原第 1 層（`huntZone: 1`, `huntStage: 1`, `canForward: true`）。因此不可假設完成移動必定回城；以該次 POST 回應和最新 `/huntInfo` 為準。

Autoy 僅在新鮮角色資料回報 `actionState: 1` 與 `canComplete: true` 時顯示「完成移動」。完成後重新讀取 `/heroes` 和 `/huntInfo`，若由死亡復原流程觸發，runner 會繼續移動、重生／轉生並在確認隊伍存活後恢復狩獵。

最新「完成移動-大草原」錄製確認先送出 `POST /api/move/complete`，成功後遊戲立即讀取 `GET /api/zoneUsers`。此摘要只記錄必要的去識別化位置和欄位；原始 `.js` 錄製包含角色及區域玩家資料，留在本機、不應提交。
