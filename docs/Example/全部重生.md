# 全部重生 API 錄製摘要

原始瀏覽器錄製檔 `全部重生.js` 保留在本機且由 Git ignore 排除，因為原始回應含角色與帳號資料。

## 已確認請求

| 欄位 | 值 |
| --- | --- |
| 操作 | 遊戲中的「全部重生」 |
| 方法與端點 | `POST /api/heroes/reviveAll` |
| Request body | 未觀察到 |
| HTTP 狀態 | 200 |
| 回應 | `heroes` 角色陣列 |

一般死亡角色（`hp: 0`, `perished: false`）進入 `actionState: 3`，回傳未來的 `actionCompleteTime`，且 `canComplete: false`。錄製時間約為開始後 10 分鐘。死透角色（`perished: true`）保持原狀，這個端點不會替它轉生。

## Autoy 行為

自動狩獵 runner 會依每位出戰角色回傳的 `actionCompleteTime` 等待，加入短暫安全緩衝；不把約 10 分鐘寫死，也不會時間一到就直接送完成請求。重新讀取 `/heroes` 後，只有一般死亡角色最新狀態為 `actionState: 3` 且 `canComplete: true` 時，才逐位呼叫已錄製的 `POST /api/heroes/{heroId}/completeAction`。未勾選角色若也一般死亡，因 `reviveAll` 是帳號批次端點，Autoy 會停止避免擴大復原範圍。

若啟動或完成端點結果不明確，不自動重送；先重新讀取角色狀態。Auto runner 停止時仍可在介面手動執行。
