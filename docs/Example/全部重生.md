# 全部重生 API 錄製摘要

原始瀏覽器錄製檔 `全部重生.js` 保留在本機且由 Git ignore 排除，因為原始回應含角色與帳號資料。

## 已確認請求

| 欄位 | 值 |
| --- | --- |
| 操作 | 遊戲中的「全部重生」 |
| 方法與端點 | `POST /api/heroes/reviveAll` |
| Request body | 未觀察到 |
| HTTP 狀態 | 200 |
| 回應 | `heroes` 角色陣列 |

一般死亡角色（`hp: 0`, `perished: false`）進入 `actionState: 3`，回傳未來的 `actionCompleteTime`，且 `canComplete: false`。錄製時間約為開始後 10 分鐘。死透角色（`perished: true`）保持原狀，這個端點不會替它轉生。

## Autoy 行為

以每位角色回傳的 `actionCompleteTime` 排定重新讀取時間，加入短暫安全緩衝；不要把 10 分鐘寫死，也不要時間一到就直接送出完成請求。重新讀取 `/heroes` 後，只有該角色最新狀態為 `actionState: 3` 且 `canComplete: true` 時，才允許使用者明確按下「完成重生」。實際完成行動沿用已錄製的 `POST /api/heroes/{heroId}/completeAction`。

若完成端點回應不明確，不自動重送；先重新讀取角色狀態。死透角色的轉生端點仍待錄製。
