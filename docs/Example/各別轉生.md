# 個別轉生 API 摘要

## 已觀察到的操作

Console recorder 顯示角色 `622` 執行：

```text
POST /api/heroes/622/reincarnate
HTTP 200
```

Autoy 會以 `{heroId}` 對應單一角色。提供的 `各別轉生.js` 匯出內容沒有這一筆 POST（僅在 Console 即時訊息看到），因此 request body 與成功 response 欄位尚未確認。介面暫時不送 request body；若伺服器拒絕，會顯示錯誤並要求先重新讀取，不會自動重試。

## 安全條件

- 自動狩獵執行中，只對勾選出戰且最新資料為 `perished: true` 的角色呼叫單角端點；每位角色各送一次，不需要阻塞 runner 的人工確認。
- runner 停止時，介面仍提供「單獨轉生」按鈕，點擊前再次確認角色與操作。
- POST 後立即重新讀取 `/heroes`；只有確認該角色已不再是 `perished: true` 才繼續下一位並恢復自動狩獵。
- 若 API 失敗或重讀後仍是死透，不自動重複送出；停止該帳號 runner 並提醒確認狀態。

請重新匯出包含 `POST /heroes/{heroId}/reincarnate` 的 recorder logs，補齊 request body、response 與轉生後角色欄位，再更新本摘要及 `../api-contract.md`。
