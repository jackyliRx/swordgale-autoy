# 死亡狀態判定（已錄製）

來源：本機 `死亡狀態與完成行動.js` 錄製檔中的 `GET /api/heroes` 與
`GET /api/heroes/{heroId}` 回應。此文件只保留判定欄位，不保存帳號或角色資料。

| 判定 | API 欄位 | Autoy 顯示／處理 |
| --- | --- | --- |
| 存活 | `hp > 0` 且 `perished !== true` | 照一般隊伍流程處理 |
| 死亡 | `hp <= 0` 且 `perished === false` | 暫停狩獵；自動移動後呼叫全部重生，依 `actionCompleteTime` 等待，再逐位完成可完成的出戰角色 |
| 死透了 | `perished === true` | 暫停狩獵；自動移動後只對該出戰角色呼叫個別轉生，重讀並確認狀態 |

## 已確認的相關寫入 API

錄製檔只觀測到：

```text
POST /api/heroes/{heroId}/completeAction
```

此端點回傳更新後的 `hero` 與 `message`，不是重生／轉生 API。

## 自動復原規則

- 完成死亡復原後，重新檢查 HP/SP 與行動狀態；全部出戰角色存活且達到設定門檻後，自動恢復狩獵。
- `reviveAll` 是帳號批次端點；如果未出戰角色也一般死亡，自動流程停止以避免影響未勾選角色。
- 轉生請求若回應不明確或重讀後角色仍死透，停止且不自動重送。

手動操作按鈕只在 runner 停止時提供為補救方式；完整 API 細節仍見 `../api-contract.md` 與 `各別轉生.md`。
